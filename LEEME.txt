------------------------------------------------------------------------
  DÓNDE SE GUARDAN LOS DATOS
------------------------------------------------------------------------

  NO es Supabase. Es FIREBASE (Realtime Database), proyecto:
      trueque-78e60
      https://trueque-78e60-default-rtdb.firebaseio.com

  El sistema guarda en este orden, y si uno falla pasa al siguiente:
      1. Firebase        → todos ven lo mismo, al instante
      2. api.php         → si lo subes a un hosting con PHP
      3. El navegador    → siempre, como respaldo sin internet

  Tu sesión (con qué cuenta entraste) NUNCA se sube: queda en tu equipo.

  Para cambiar de proyecto de Firebase: js/14-nube.js, arriba del todo.


------------------------------------------------------------------------
  LOS 3 PASOS PARA QUE SEA SEGURO DE VERDAD
------------------------------------------------------------------------

  Mientras la base esté abierta, cualquiera con el enlace puede leerla o
  borrarla. Estos 3 pasos lo cierran:

  1. Publica la web con HTTPS (Firebase Hosting es gratis).

  2. Firebase → Authentication → activa "Google" y agrega tu dominio en
     Authorized domains. (Sin esto, el botón de Google nunca funciona;
     por eso ahora se esconde solo cuando abres el archivo local.)

  3. Firebase → Realtime Database → Reglas → pega esto y PUBLICA:

     {
       "rules": {
         "truequea": {
           ".read": "auth != null",
           ".write": "auth != null",
           ".validate": "newData.hasChildren(['usuarios','articulos'])"
         }
       }
     }

  Todo esto también lo ves dentro del sistema:
  Admin → 🎨 Marca → 🔐 Seguridad.


------------------------------------------------------------------------
  LO QUE YA ESTÁ PROTEGIDO
------------------------------------------------------------------------

  · Las contraseñas NO se guardan escritas. Se guarda una huella
    (PBKDF2, 150 000 vueltas, con sal propia). Ni tú como administrador
    puedes leer la clave de alguien: solo ponerle una nueva.
  · 5 intentos fallidos = 15 minutos de bloqueo.
  · Si el correo no existe, responde igual que si la clave está mal,
    para que nadie averigüe qué correos están registrados.
  · La sesión vence a los 30 días.
  · Bitácora: quién entró, quién falló, quién cambió qué.
  · Máximo 3 administradores. Nunca se queda sin ninguno.
  · Al sincronizar se FUSIONAN los datos: ningún equipo borra lo de otro.
  · Copias de seguridad automáticas (Admin → Marca → 🛟 Copias).
